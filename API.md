# API редактора — контракт между питоном и фронтом

Питон — конвейер и бекенд, React — редактор. Это единственная точка их
стыка: **менять контракт можно только правкой этого файла**, иначе фронт и
бек разъедутся.

Сервер поднимается командой `char2rig edit <имя> [--port 8765]` и работает
с одним персонажем — тем, чью папку ему дали. Всё под `/api/`; корень
отдаёт собранный фронт.

## Разработка

- Vite на `:5173`, в `vite.config` прокси `/api` → `http://127.0.0.1:8765`.
  CORS в питоне не нужен — с прокси всё однооригинно.
- Сборка кладётся в `char2rig/web/`, питон отдаёт её статикой с корня.
  Пока сборки нет, отдаётся старая ванильная страница `editor.html`.

## Кадр и координаты

Всё — в пикселях исходного арта: `source.png`, `silhouette.png`, все карты
и слои имеют один размер `size = [w, h]`. Ось x вправо, y вниз. Никаких
кропов и смещений во фронт не приезжает: слой части сервер вкладывает
обратно в полный кадр.

## GET /api/character

Один вызов на загрузку — всё, что нужно, чтобы нарисовать любую вкладку.

```jsonc
{
  "name": "ginger",
  "size": [1024, 1536],
  "template": "biped_tail",
  "triage": "yellow",
  "bones": [
    { "name": "torso", "parent": null, "a": "pelvis", "b": "neck",
      "z": 20, "color": [244, 93, 93] }
  ],
  "joints":      { "pelvis": [512.0, 780.5] },   // с ручными правками
  "joints_auto": { "pelvis": [510.0, 780.5] },   // без них — база для дельт
  "radii":       { "torso": [64.0, 52.0] },
  "radii_auto":  { "torso": [64.0, 52.0] },
  "overrides": {
    "contour": true, "silhouette": false, "skeleton": true,
    "parts": false, "redraw": ["tail_1"]
  },
  "stages": { "layers": { "method": "overlap_cut+lama", "fallback": false } }
}
```

`bones` идут в порядке шаблона — **этот порядок и есть номер части** во
всех картах (`индекс + 1`, ноль зарезервирован под «ничего»). `color` —
подобранная сервером палитра, чтобы соседние кости не сливались.

**Дельты считаются от `joints_auto`, не от `joints`.** В `joints` правки
уже применены; если отсчитывать от них, правка применится второй раз.

## GET /api/contour?auto=1

`{ "points": [[x, y], …] }` — внешний контур силуэта многоугольником.
Без `auto` отдаётся сохранённая ручная версия, если она есть; с `auto=1` —
всегда свежая из автоматики (это кнопка «сбросить этап»).

## Карты: GET /api/map/…

Всегда `w * h` байт без заголовков, построчно сверху вниз. Читать так:

```js
const map = new Uint8Array(await (await fetch(url)).arrayBuffer());
const value = map[y * width + x];
```

| путь | значения |
|---|---|
| `/api/map/parts` | номер кости + 1; 0 — вне силуэта |
| `/api/map/parts-overrides` | сохранённая ручная карта частей, 0 — не тронуто |
| `/api/map/fill?part=<имя>` | 0 — часть сюда не достаёт, 1 — родные пиксели, 2 — кайма за силуэтом, 3 — область под чужой частью (её достраивает LaMa) |
| `/api/map/redraw?part=<имя>` | 0 — нет правки, 128 — «оставить как есть», 255 — «дорисовать заново» |

**Почему байты, а не картинка.** Номер части — это данные, а картинку
браузер вправе перегнать под цветовой профиль монитора, и номер поедет.
Показывать карту, конечно, надо цветом, но раскрашивает её фронт сам.

## Картинки: GET /api/image/…

`source.png`, `silhouette.png`, `silhouette.overrides.png`, `preview.gif`,
`preview_strip.png` — как есть. Отдельно:

- `/api/image/layer.png?part=<имя>` — RGBA-слой части, уже вложенный в
  полный кадр. Это то, что уедет в движок: с нахлёстом, растушёванным краем
  и достроенными областями.

## POST /api/save и POST /api/rebuild

Тело одно и то же — всё состояние правок разом. Так вкладки не теряют
работу друг друга: ушёл с вкладки не сохранившись — и правка пропала.

```jsonc
{
  "joints":       { "elbow_l": [12.5, -3.0] },   // дельты от joints_auto
  "radius_scale": { "arm_fore_l": 1.2 },         // множители толщины
  "contour":      [[x, y], …] | null,            // null — не трогали
  "strokes":      "data:image/png;base64,…" | null,  // кисть по силуэту
  "parts":        "data:image/png;base64,…" | null,  // карта частей
  "redraw":       { "tail_1": "data:image/png;base64,…" },  // достройка
  "start":   "background" | "pose" | "segment" | "layers",
  "preview": "mesh" | "parts"
}
```

`null` и отсутствующий ключ значат «не трогали, оставь как было». Пустая
карта (ни одного закрашенного пикселя) значит «правку сняли» — сервер
удаляет соответствующий файл.

`/api/save` отвечает `{"ok": true}`. `/api/rebuild` сохраняет и тут же
гоняет конвейер, отвечая `{"triage": "green|yellow|red", "fit_inside": 0.93}`;
на упавшем конвейере — 500 с текстом ошибки (её показывать человеку).

### Как кодировать правку в PNG

Растровые правки уезжают холстом через `canvas.toDataURL('image/png')`:

- **значение — в красный канал**, `alpha = 255` там, где закрашено;
- `alpha = 0` там, где не трогали (RGB там неважен).

Непрозрачные пиксели PNG отдаёт байт в байт — проверено в Edge, ноль
расхождений на 1852 пикселях. У прозрачных RGB теряется из-за
предумножения, поэтому «не тронуто» и кодируется прозрачностью.

| правка | значения в красном канале |
|---|---|
| `strokes` (силуэт) | 255 — это тело, 128 — это фон |
| `parts` | номер кости + 1 в порядке `bones` |
| `redraw` (достройка) | 255 — дорисовать заново, 128 — оставить как есть |

### С какого этапа пересчитывать

`start` — самый ранний тронутый этап, а не текущая вкладка:

| что тронули | start |
|---|---|
| контур силуэта или кисть по силуэту | `background` |
| суставы или толщина костей | `pose` |
| карта частей | `segment` |
| достройка | `layers` |

Ничего не тронули — `pose` (дёшево и безопасно).

`preview` выбирает, чем рисовать `preview.gif`: `mesh` — деформацией сетки
(персонаж гнётся как единое тело), `parts` — жёсткими нарезанными частями.
Правка частей и достройки **на сетке не видна вовсе**: веса сетки идут от
капсул скелета, а не от масок. Смотреть их надо с `preview: "parts"`.

## Правила, которые нельзя нарушать

1. **Правка — оверлей, а не редактирование результата** (принцип №1 в
   DESIGN.md). Фронт никогда не пишет в `masks/`, `layers/`, `rig.json` —
   только шлёт правки, а пересчитывает их конвейер.
2. **Совпавшее с автоматикой в оверлей не пишется.** Мазок, который вернул
   пиксель тому же хозяину, должен обнулиться, иначе файл правок подменит
   собой весь этап и перегенерация перестанет что-либо менять.
3. **Растровая правка помнит хеш арта.** Перегенерили `source.png` — правка
   не применяется молча, а помечается флагом в `status.json`. Хеш ставит
   сервер, фронту об этом думать не надо.
4. **Порядок инструментов — порядок конвейера.** Силуэт → скелет → части →
   достройка → веса сетки → движения. Правят там, где ошибка возникла.
