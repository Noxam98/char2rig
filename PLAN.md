# План фазы 0 — вертикальный срез

Цель: `PNG персонажа → нарезка на части → риг → машущий конечностями GIF`,
всё через CLI без интерфейсов. Отвечаем на главный вопрос проекта: работают
ли сегментация и inpaint на целевом стиле (painterly-антропоморфы, полосы).

## Структура пакета

```
char2rig/
  __main__.py     # python -m char2rig <команда>
  cli.py          # команды: demo, process, recut, swing, edit
  template.py     # шаблоны скелетов (biped, biped_tail): суставы, иерархия,
                  # части-капсулы, радиусы, z-order
  character.py    # папка персонажа: source.png, skeleton.json(+overrides),
                  # masks/, layers/, rig.json, preview.gif, status.json
  stages/
    background.py # удаление фона: rembg → фоллбек: готовая альфа исходника
    pose.py       # посадка шаблона скелета по bbox силуэта + уточнение
                  # DWPose (rtmlib), если установлен и уверенность высокая
    segment.py    # SAM2 (ultralytics) с подсказками из костей → фоллбек:
                  # капсульные маски прямо из скелета; конфликтные пиксели —
                  # ближайшей кости
    layers.py     # нарезка с нахлёстом в суставах и растушёванной альфой,
                  # z-order, inpaint скрытых областей: LaMa → фоллбек cv2
    rig.py        # пивоты в суставах, привязка частей к костям, rig.json
    render.py     # FK-сборка, стресс-свинг, preview.gif + спрайт-лента PNG
  demo.py         # процедурный полосатый кот из капсул шаблона
```

## Ключевые решения

- **Два уровня зависимостей.** `requirements.txt` — ядро (numpy, pillow,
  opencv): работает на любой машине без GPU. `requirements-ml.txt` — rembg,
  rtmlib+onnxruntime, SAM2 (ultralytics), LaMa; torch — колёса cu126
  (Pascal sm_61 жив в torch ≤ 2.7.x).
- **Каждый нейро-этап обязан иметь фоллбек без моделей** — конвейер целиком
  прогоняется на голом ядре. Использованные фоллбеки пишутся в
  `status.json`, чтобы отличать «настоящий» прогон от деградированного.
- **Демо-кот** рисуется процедурно из тех же капсул скелета, с полосами —
  это сразу тест главного риска (швы на полосатом мехе в суставах), не
  требующий ни моделей, ни образцов.
- **Свинг-тест:** синусоидальные качания (плечи ±35°, локти ±20°, бёдра
  ±30°, колени ±20°, хвост волной ±25°, голова ±8°), 24 кадра → GIF +
  спрайт-лента PNG (лента — чтобы результат было видно в git/по Read).
- **Скелет biped_tail, ~15 частей:** голова, торс, плечо/предплечье/кисть
  ×2, бедро/голень/стопа ×2, хвост из 2 частей (3 кости). Уши пока в голове.

## Что показал первый прогон (демо-кот, ядро без моделей)

Ответ на главный вопрос по швам — **полосы через суставы не рвутся**:
щели 0.004% от площади тела, непокрытых пикселей 0, триаж зелёный.
По дороге всплыло четыре вещи, все закрыты в коде:

- **Нахлёст должен быть плотным, а не растушёванным по всей ширине.**
  Полупрозрачный заезд красив, пока сосед лежит сверху; стоит руке отойти —
  из-под неё торчит призрак. Теперь заезд непрозрачный, гаснут только
  последние ~3 px.
- **Нахлёст даётся шапками вокруг суставов, а не по всему контуру части.**
  Торс, отрастивший 30 px во все стороны, при взмахе руки выставлял наружу
  прямоугольный обрубок.
- **Проверка «дырки внутри силуэта» — ложная.** Она красит в красный
  подмышку и просвет между ног. Настоящая проверка: сравнить покрытие
  слоями с формой скелета в той же позе (капсулы) — что скелет считает
  телом, а слои не закрыли, то и щель.
- **Достройка каймы за силуэтом — ближайшим пикселем, а не cv2.inpaint.**
  Диффузия размазывала усы в жирные чёрные полосы.

## Что показала ML-обвязка (демо-кот на непрозрачном фоне, GTX 1070)

Все четыре модели заведены и работают; итог тот же зелёный (посадка 0.000%,
швы 0.004%), но выводы про модели неожиданные:

- **rembg** снимает градиентный фон точно в исходный bbox — единственный
  этап, где модель безоговорочно лучше фоллбека (заливка от рамки на
  градиенте разваливается).
- **DWPose детектирует антропоморфа** (уверенность 0.64 — детектор в rtmlib
  обучен на HumanArt, то есть на рисованных людях). Но его подгонка
  подобием оказалась **хуже** посадки по bbox (IoU 0.92 против 0.95), и
  предохранитель её отклонил. Вывод: в канонической A-позе силуэт говорит о
  скелете больше, чем детектор. Польза от DWPose появится там, где поза
  далека от шаблонной.
- **SAM2 не даёт риггуемых частей.** По подсказке-точке из кости он
  возвращает: торс → 98% силуэта (весь кот), плечо → 98%, зато кисти и
  стопы → IoU 0.86–0.95. Отрицательные подсказки на соседних костях
  ultralytics игнорирует — результат не меняется. Хуже того, даже хорошие
  маски **ломают риг**: SAM знает, что «это лапа», но его граница проходит
  не по голеностопу, и перенос пикселей через неё поднял щели с 0.004% до
  1.7%. Поэтому разрезы по суставам оставлены капсулам, а SAM2 решает
  только на окраинах, куда скелет не дотянулся.
- **LaMa** достраивает области, закрытые чужой частью спереди (у демо-кота
  таких ~600 px). На перекрестьях конечностей в реальном арте её роль
  вырастет.

Отдельно всплыло, что проверка мерила две разные беды одним числом. Теперь
у каждой своё, и меряется там, где осмысленно: **швы** — прирост щелей в
движении (стресс-тест), **посадка** — IoU капсул скелета с силуэтом (этап
позы), **непокрытые пиксели** — этап слоёв. Щели в позе покоя из триажа
убраны: у живого арта силуэт всегда немного не совпадает с капсулами
(клочья шерсти, одежда), это не дефект.

## Генератор обучающего набора и что он сразу показал

`python -m char2rig dataset --count 1000` рисует персонажей со случайными
пропорциями, позой и окрасом и отдаёт к каждому точную разметку: карта
частей (какой кости принадлежит пиксель) и координаты суставов. Такой
разметки нет ни в одном публичном наборе — там части размечены по смыслу,
а ригу нужен разрез по суставу.

Первым делом набор пригодился не для обучения, а как **измерительная
линейка для фоллбека**. Оказалось, что правило «пиксель достаётся
ближайшей капсуле» совпадает с истиной всего на 0.67 IoU (бёдра — 0.30:
их съедает толстый торс). Замена на «верхняя по z из накрывших капсул» —
то есть так, как арт и рисуется слоями, — даёт **0.91 IoU и 0.96
попиксельной точности**, без всякого обучения. Швы демо-кота при этом
упали с 0.059% до 0.020%.

Вывод на будущее: прежде чем учить сеть, стоит померить, сколько
выжимается из геометрии. Порог для сети теперь известен — 0.91.

## Первый настоящий кот: что сломалось и что нет

Painterly-кот от Gemini, поза почти каноническая. Конвейер прошёл насквозь;
туловище, голова, руки и ноги двигаются чисто, швов на полосах не видно —
главный вопрос фазы 0 на живом арте отвечен так же, как на демо. Сломалось
другое, и по дороге вылезли настоящие баги:

- **LaMa дополняет вход до кратности восьми** и отдаёт кадр вместе с
  добавкой — конвейер падал на несовпадении форм. Обрезаем обратно.
- **Пути к весам были относительными**: запуск из любой папки, кроме корня
  репы, молча не находил модели и уходил в фоллбек.
- **Детектор вынес лодыжку за силуэт**, и вся нога уехала наружу. Общий IoU
  при этом даже вырос за счёт других суставов, так что промах не заметили.
  Теперь точка вне силуэта не берётся вовсе.
- **Шаблон кладёт хвост туда, где он был у эталона.** У живого кота он
  уходит куда угодно, а детекторы поз про хвосты не знают (в COCO их нет).
  Хвост теперь ищется прямо в силуэте: это тот кусок арта, до которого не
  дотянулась ни одна капсула. Отличать его от каймы вдоль руки надо по
  **глубине выроста**, а не по близости к корню — кайма проходит вплотную.
- **Радиусы костей брались из шаблона.** Меряем толщину поперёк кости, беря
  меньшую из сторон: рука, прижатая к телу, наружу выходит сразу, а внутрь
  луч уходит через весь торс и намерил бы его ширину.
- **`fit_iou` оказался негодной мерой качества посадки.** Уши, клочья
  шерсти и пушистый хвост капсулой не описываются в принципе, и на живом
  арте IoU упирается в потолок, не связанный с качеством рига. Дефект —
  это когда скелет считает телом то, где арта нет; триаж теперь смотрит на
  **долю капсул внутри силуэта**. Сравнивать кандидатов позы по-прежнему
  честно по IoU: радиусы у них одни и те же.

**Что осталось сломанным: хвост разваливается на куски при качании.**
Причина не в нахлёсте и не в радиусах — их я подтянул, и основание хвоста
перестало доставаться жирной капсуле бедра. Дело в самой модели: сильно
загнутый хвост описывается тремя жёсткими хордами, каждая следующая
накапливает поворот родителя, и на 180-градусной дуге куски расходятся.
Лечится не константами, а сменой подхода — больше костей на загнутых
цепочках либо деформация полосой вместо жёстких частей. Отдельная задача.

- **Amateur Drawings Dataset** (Meta, MIT): 178 тыс. рисунков с bbox,
  масками и суставами, а к нему — детектор и оценщик позы, **дообученные
  на рисунках**. Оценщик подключён: это `drawnpose.py`. Веса лежат в
  TorchServe-архиве, но сеть внутри — обычный SimpleBaseline (ResNet-50 +
  три деконв-слоя, COCO-17, вход 192×256), поэтому поднимается на голом
  torch, без стека mmcv/mmpose (который на Python 3.13 и не собрался бы).
- **ChildlikeSHAPES** (Meta, 2025): 16 тыс. рисунков с пиксельной
  разметкой на 25 частей. Части семантические, не по суставам — годится
  как претрен и как таксономия, но не как целевая разметка.
- **See-through** (SIGGRAPH 2026, Apache-2.0): одна аниме-картинка → PSD
  из 23 слоёв с достройкой скрытых областей. Риггинг авторы не делают, то
  есть это возможная замена наших `segment`+`layers`, а не конкурент. **Но
  на нашей 1070 не запустится:** пайплайн идёт в bf16 (Pascal его не умеет
  вовсе), пины — torch 2.8+cu128, откуда sm_61 уже выпал, а их вариант «для
  8 ГБ» — NF4 через bitsandbytes, которому нужен Turing и новее. Оценивать
  результат — через их HF Space с ZeroGPU (1–2 разбора в день бесплатно),
  вернуться к локальному запуску, если сменится видеокарта.
  Рядом `CubismPartExtr` — сбор данных из моделей Live2D, то есть из
  настоящих продакшн-ригов.
- **e621** — домен нашего стиля, годится как источник реального арта для
  проверок; для обучения LoRA стиля брать чужие работы не станем.

## Кто лучше находит суставы (замер на наборе с истиной)

Ошибка — среднее расстояние до истинного сустава в долях роста, 16 образцов
со случайными пропорциями и позами:

| метод | все суставы | только конечности | хуже bbox |
|---|---|---|---|
| посадка по bbox | **0.056** | **0.052** | — |
| drawn_pose + подобие | 0.064 | 0.055 | 4 из 6 |
| DWPose + подобие | 0.078 | 0.062 | 7 из 13 |
| drawn_pose + посадка по суставам | 0.087 | 0.086 | 8 из 10 |
| DWPose + посадка по суставам | 0.107 | 0.114 | 14 из 16 |

Ни один детектор не обыграл вписывание шаблона в силуэт — ни на всех
суставах, ни на тех, которые они собственно и предсказывают. При этом
`drawn_pose` кладёт точки заметно точнее DWPose (уверенность 0.87 против
0.64, запястья попадают на лапы, лодыжки на стопы) — просто этого
недостаточно, чтобы обыграть силуэт.

Оговорка: позы в наборе умеренные по построению, и силуэтная рамка на них
работает хорошо. Проверка не отвечает на вопрос про по-настоящему
неканоническую позу (руки над головой, персонаж сидит) — а именно ради неё
детекторы в конвейере и оставлены. Стоят они ничего: каждый даёт кандидата,
а выбирает силуэт по IoU капсул.

## Настройка машины (Windows 10 + GTX 1070)

1. Драйвер NVIDIA — уже стоит (536.99), проверка `nvidia-smi`.
2. `python -m venv .venv` и `.venv\Scripts\python.exe -m pip install -r
   requirements.txt`. Питона в PATH нет, звать по полному пути.
3. ML-слой: `-r requirements-ml.txt`, torch отдельно:
   `pip install "torch<2.8" --index-url https://download.pytorch.org/whl/cu126`
   (Pascal sm_61 выпал из torch 2.8+). Соединение рвёт большие загрузки —
   колёса надёжнее тянуть `curl.exe -C - --retry 30` и ставить из файла.
4. Положить арт в `samples/` (например `samples/cats.png` — лист с тремя
   котами; конвейер умеет резать лист на отдельных персонажей по альфе
   после удаления фона).

## Ручные действия человека в фазе 0

- положить образцы в `samples/`,
- смотреть гифки и говорить «ок / не ок»,
- при кривом скелете — подвинуть суставы: `char2rig edit <имя>` поднимает
  локальную страницу с перетаскиванием, правки ложатся дельтами в
  `skeleton.overrides.json`. Окно cv2 не подошло: opencv в ядре стоит
  headless-сборкой, а тянуть ради редактора Qt — перебор.
