# char2rig — дизайн

Цель: конвейер «картинка персонажа → анимируемый 2D-персонаж» с максимальной
автоматизацией и ручными правками поверх автоматики.

## Принципы

1. **Правки — оверлеи, а не редактирование результата.** Каждая ручная правка
   хранится отдельно от автоматического выхода: сдвинутый сустав — дельта
   координат, мазок по маске — записанный штрих, привязанный к ID части тела.
   При перезапуске этапа правки переприменяются поверх нового результата.
   Если перегенерирован сам арт — растровые правки инвалидируются с флагом,
   а не применяются молча.
2. **Перезапуск с любого этапа.** Конвейер — DAG с кешированием по хешам
   входов: правка на этапе N пересчитывает только этапы после N.
3. **Автотриаж вместо тотальной проверки.** Конвейер сам проверяет результат
   и красит персонажа в зелёный/жёлтый/красный. Человек открывает только
   жёлтых и красных.

## Конвейер

| # | Этап | Автоматика | Ручная правка |
|---|------|-----------|----------------|
| 1 | Арт | SDXL + LoRA стиля + ControlNet (фикс. A-pose, нейтральный фон); либо импорт PNG + удаление фона (BiRefNet) | перегенерация, inpaint региона |
| 2 | Скелет | DWPose + авто-подгонка шаблонного скелета по силуэту | перетащить суставы |
| 3 | Сегментация | SAM2 с подсказками из суставов → маска на часть | кисть/ластик, перенос куска между частями |
| 4 | Слои | порядок глубины, inpaint скрытых областей (LaMa / SD1.5-inpaint) | z-order, перегенерация куска |
| 5 | Риг | разрезы по суставам с нахлёстом и растушёванной альфой, пивоты, привязка костей | пивоты, нахлёсты |
| 6 | Анимации | ретаргет библиотеки клипов на стандартный скелет, адаптация к пропорциям | правки кривых (редко) |
| 7 | Экспорт | Spine JSON / формат движка | — |

## Этап 1 подробнее: что подаётся на вход генерации

Вход нейронки — не картинка, а **карточка персонажа**:

1. **Текстовое описание** («рыжий полосатый кот-воин в кожаной сбруе») —
   становится промптом вместе с триггер-словами стиля.
2. **LoRA стиля** — тренируется один раз на одобренных артах игры и держит
   единый стиль всех персонажей.
3. **Шаблон тела** — выбор из короткого списка (бипед, бипед+хвост,
   digitigrade-ноги и т.п.). Шаблон даёт:
   - ControlNet-карту позы: фиксированная A-pose, единый масштаб и
     кадрирование — все персонажи выходят в одной канонической позе;
   - список ожидаемых частей тела для сегментации и рига.
4. **Нейтральный фон** — задаётся промптом, чтобы не тратить качество
   на удаление фона.

Хвост ControlNet-позой не управляется (в OpenPose его нет) — его наличие
контролируется промптом, а соответствие шаблону проверяет QA: «шаблон без
хвоста, а хвостовые пиксели найдены» → жёлтый флаг.

Генерится 4–8 вариантов, человек выбирает лучший (или перегенерирует /
inpaint'ит детали) — это точка правки этапа 1. Выбранный PNG идёт дальше
по конвейеру.

**Альтернативный вход — импорт готовой картинки** (Midjourney и т.п.):
шаблон указывается руками. Если поза далека от канонической, сегментации
будет труднее (больше перекрытий → больше ручных правок); опционально —
нормализация позы через img2img + IP-Adapter, с риском дрейфа деталей.

## Стресс-тест (ключ к автоматизации)

После сборки рига конвейер сам испытывает персонажа: прокрутка каждого
сустава на ±40°, прогон всех анимаций, рендер 3-секундного GIF. Программно
ловятся:

- щели в суставах (недостаточный нахлёст),
- непокрытые масками непрозрачные пиксели,
- артефакты inpaint в открывшихся областях,
- низкая уверенность детектора суставов,
- расхождение полос/паттерна на швах (важно для полосатых персонажей).

Человек смотрит GIF: approve или клик в редактор проблемного этапа.

## Скелет

Фиксируется один стандартный скелет на всех персонажей — это делает
библиотеку анимаций переиспользуемой: новый персонаж получает все клипы
автоматически.

Базовый гуманоид (~15 частей) — общий для всех персонажей. Видовые
особенности — **опциональные цепочки** поверх базы:

- **хвост** — 3–4 кости, только у хвостатых шаблонов,
- **digitigrade-ноги** — три сегмента (бедро / голень / плюсна+стопа),
- **уши** — 1 кость на ухо, опционально.

Библиотека анимаций пишется под базовый скелет и подходит всем — с хвостом
и без. Анимации опциональных цепочек (покачивание хвоста в idle) — отдельные
**аддитивные слои**, применяются только если часть у персонажа существует.
Бесхвостый персонаж этих слоёв просто не имеет — ничего не ломается.

## Хранилище

Файлы в открытых форматах, по папке на персонажа, всё в git:

```
characters/<name>/
  source.png              # исходный арт
  skeleton.json           # авто-скелет
  skeleton.overrides.json # ручные дельты суставов
  masks/                  # PNG-маска на часть
  masks.overrides/        # штрихи правок
  layers/                 # RGBA-слои с достроенными областями
  rig.json                # риг (пивоты, z-order, кости)
  preview.gif             # стресс-тест
  status.json             # хеши этапов, результаты проверок, триаж
```

## Стек

- **Бекенд:** Python, FastAPI + воркер с очередью; модели грузятся/выгружаются
  по этапам (бюджет RAM ~32 ГБ, VRAM 8 ГБ).
- **Модели:** DWPose (rtmlib, ONNX), SAM2 small/base, LaMa, SD1.5-inpaint,
  BiRefNet. Все работают на GTX 1070; CPU-fallback для штучной обработки.
- **Облако (по необходимости):** SDXL-генерация и тренировка LoRA — RunPod /
  Replicate. Этап генерации — подключаемый бекенд (локальный ComfyUI и
  облачный API взаимозаменяемы).
- **Фронт (фаза 2):** веб-редактор на canvas — триаж-дашборд, кисть по маскам,
  перетаскивание суставов, живой предпросмотр анимации в редакторе.
- PyTorch фиксируем на версиях с поддержкой Pascal (sm_61).

## Фазы

- **Фаза 0 — вертикальный срез.** CLI без UI: 3–5 реальных артов →
  DWPose → SAM2 → наивные разрезы → LaMa → собранный персонаж машет
  конечностями в GIF. Отвечает на главный вопрос: работают ли сегментация
  и inpaint на целевом стиле.
- **Фаза 1** — DAG с кешем, оверлеи правок, автопроверки, батч.
- **Фаза 2** — веб-UI: триаж + редакторы масок/скелета.
- **Фаза 3** — генерация (LoRA стиля, фикс позы), библиотека анимаций,
  экспортёры в движок.

## Известные риски

| Риск | Смягчение |
|------|-----------|
| Позные детекторы обучены на людях — антропоморфы (морда, хвост, digitigrade) детектятся плохо | стандартизованная поза генерации → посадка шаблонного скелета по силуэту + ручная доводка |
| Полосатый мех: швы в суставах заметны | растушёванный нахлёст, меш-деформация, проверка швов в стресс-тесте |
| Стиль inpaint «плывёт» | LoRA на стиле, маленькие области достройки |
| Запечённый свет едет при повороте конечностей | норма для cutout; в движении не критично |
| Виды сбоку/сзади из фронтального арта | вне скоупа чистой 2D-ветки; при необходимости — 3D-прокси (TripoSR → Mixamo → рендер спрайтов) |
